# Техническое описание датасета HateXplain

## 1. Общая информация

Для проекта был выбран датасет HateXplain.

HateXplain — англоязычный набор текстовых сообщений из социальных сетей Gab и Twitter. Датасет предназначен для работы с языком ненависти и оскорбительным контентом.

В разметке используются три класса:

- `hatespeech` — сообщения, содержащие язык ненависти;
- `offensive` — оскорбительные сообщения;
- `normal` — сообщения, которые не относятся к двум предыдущим категориям.

Каждое сообщение размечалось тремя аннотаторами.

В рамках нашего проекта текстовые сообщения планируется преобразовать в аудиозаписи с помощью технологии TTS (Text-to-Speech).

TTS позволяет автоматически озвучивать текст синтезированным голосом. Таким образом, текстовый датасет можно использовать как источник данных для задачи классификации голосовых сообщений.

Изначальная постановка учебного кейса немного отличается от классов HateXplain. Возможность использовать категорию hate speech при адаптации постановки задачи была согласована с преподавателем.

## 2. Структура данных

Исходный датасет представлен в формате JSON.

Каждая запись соответствует одному сообщению и содержит несколько основных элементов:

- `post_id` — идентификатор сообщения;
- `post_tokens` — текст сообщения, разбитый на отдельные токены;
- `annotators` — разметка сообщения тремя аннотаторами;
- `rationales` — информация о фрагментах текста, которые аннотаторы считали важными для определения класса.

Для каждого аннотатора в поле `annotators` указывается:

- выбранный класс (`hatespeech`, `offensive` или `normal`);
- идентификатор аннотатора;
- объект или группа, на которую направлено сообщение, если это применимо.

Готового итогового класса в используемой версии данных нет. Поэтому в ходе анализа итоговая метка определялась по принципу большинства: если минимум два из трёх аннотаторов выбирали один класс, он принимался за итоговый класс сообщения.

Также по идентификатору сообщения можно определить источник данных: Gab или Twitter.

## 3. Объём данных

Исходный датасет содержит 20 148 сообщений.

В ходе анализа для каждого сообщения была определена итоговая метка по большинству голосов трёх аннотаторов. Для 919 сообщений большинство определить не удалось, поэтому такие записи были исключены из дальнейшего анализа.

После этого осталось 19 229 сообщений.

Распределение по классам:

| Класс | Количество сообщений | Доля |
|---|---:|---:|
| `normal` | 7 814 | 40,64% |
| `hatespeech` | 5 935 | 30,86% |
| `offensive` | 5 480 | 28,50% |
| **Всего** | **19 229** | **100%** |

Классы распределены достаточно равномерно. Самым большим является класс `normal`, но сильного дисбаланса между тремя классами нет.

По источникам данные распределены следующим образом:

| Источник | Количество сообщений |
|---|---:|
| Gab | 10 451 |
| Twitter | 8 778 |
| **Всего** | **19 229** |

Большая часть сообщений имеет небольшую длину. Средняя длина составляет около 23 токенов, медианная — 20 токенов.

Около 70% сообщений содержат не более 30 токенов, а примерно 98% — не более 50 токенов. Это удобно для дальнейшего преобразования сообщений в короткие аудиозаписи с помощью TTS.


## 4. Качество разметки

Каждое сообщение в HateXplain размечалось тремя независимыми аннотаторами.

По результатам анализа были получены следующие значения согласия между аннотаторами:

| Согласие аннотаторов | Количество сообщений | Доля |
|---|---:|---:|
| Все три выбрали один класс | 9 845 | 48,86% |
| Два из трёх выбрали один класс | 9 384 | 46,58% |
| Все три выбрали разные классы | 919 | 4,56% |

Таким образом, для 95,44% сообщений можно определить итоговый класс по большинству голосов.

Записи, для которых все три аннотатора выбрали разные классы, были исключены из дальнейшего анализа. Это позволяет уменьшить количество неоднозначных примеров в итоговой выборке.

Дополнительным преимуществом датасета является наличие поля `rationales`. В нём указаны фрагменты сообщения, которые аннотаторы считали важными при выборе класса. Это позволяет лучше понимать причины присвоения определённой метки.

В целом качество разметки можно считать достаточно высоким для учебного проекта: большинство сообщений имеют согласованную оценку нескольких аннотаторов, а спорные записи можно исключить перед обучением модели.

## 5. Применимость для задачи классификации

HateXplain подходит для проекта по нескольким причинам:

- содержит три близких к нашей задаче класса: `hatespeech`, `offensive` и `normal`;
- имеет достаточно большой объём данных;
- сообщения в основном короткие, поэтому их удобно преобразовывать в аудио;
- возможность использовать категорию hate speech была согласована с преподавателем.

Так как исходный датасет текстовый, для получения голосовых сообщений планируется использовать TTS (Text-to-Speech).

## 6. Ограничения и особенности

Основное ограничение — отсутствие готового аудио. Голосовые записи потребуется создавать отдельно с помощью TTS.

Также в ходе анализа был обнаружен перекос распределения классов между Gab и Twitter. При формировании итоговой выборки это желательно учитывать.

Перед использованием данных также потребуется удалить служебные элементы текста, конфликтующие дубликаты и другие элементы, которые могут мешать корректному озвучиванию.

## 7. Вывод

HateXplain можно использовать как основной источник данных для проекта.

Датасет имеет подходящие классы, достаточно большой объём и качественную разметку несколькими аннотаторами. После небольшой очистки и преобразования текста в аудио с помощью TTS его можно использовать для обучения модели классификации голосовых сообщений.
