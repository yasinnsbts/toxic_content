# Техническое описание датасетов для классификации токсичного голосового контента

## 1. Общая информация

В рамках проекта планируется исследовать возможность автоматического распознавания токсичного содержания в голосовых сообщениях.

Для формирования обучающих данных выбраны два текстовых датасета:

1. **HateXplain** — англоязычный датасет сообщений из Twitter и Gab с классами `hatespeech`, `offensive` и `normal`.
2. **Toxic Russian Comments** — русскоязычный датасет комментариев из социальной сети OK.ru с разметкой по типам токсичного содержания.

Оба исходных датасета являются текстовыми. Поэтому для создания голосовых данных планируется преобразовать текстовые сообщения в аудиофайлы с помощью технологии **TTS (Text-to-Speech)**.

Основная идея исследования заключается в проведении трёх последовательных экспериментов:

- обучение и проверка модели на данных HateXplain;
- обучение и проверка модели на данных Toxic Russian Comments;
- объединение подготовленных данных и обучение общей модели с последующей проверкой её работы.

Такой подход позволит отдельно оценить работу модели на каждом источнике данных, а затем проверить, насколько объединение различных наборов данных влияет на способность модели распознавать токсичный контент.

---

## 2. Датасет HateXplain

### 2.1. Общая характеристика

HateXplain — англоязычный набор текстовых сообщений из социальных сетей Twitter и Gab, предназначенный для исследования задач определения языка ненависти и оскорбительного контента.

Датасет содержит 20 148 сообщений. Каждое сообщение размечалось тремя аннотаторами. В базовой задаче используются три класса:

- `hatespeech` — сообщения, содержащие язык ненависти;
- `offensive` — оскорбительные сообщения;
- `normal` — сообщения, которые не относятся к двум предыдущим категориям.

Помимо основной метки, HateXplain содержит информацию о целевой группе и `rationales` — фрагментах текста, которые аннотаторы считали значимыми при принятии решения.

### 2.2. Обработка разметки

Для каждого сообщения учитываются оценки трёх аннотаторов.

Если два или три аннотатора выбирают один класс, он принимается за итоговую метку сообщения.

Для 919 сообщений все три аннотатора выбрали разные классы. Такие записи исключаются из основной выборки.

После исключения неоднозначных записей остаётся 19 229 сообщений:

| Класс | Количество | Доля |
|---|---:|---:|
| `normal` | 7 814 | 40,64% |
| `hatespeech` | 5 935 | 30,86% |
| `offensive` | 5 480 | 28,50% |
| **Всего** | **19 229** | **100%** |

Распределение классов относительно равномерное, поэтому выраженного дисбаланса между тремя основными классами нет.

### 2.3. Качество разметки

Каждое сообщение HateXplain размечалось тремя независимыми аннотаторами. Авторы датасета указывают значение Krippendorff's alpha 0,46.

В нашей выборке итоговый класс определяется по большинству голосов. Сообщения, для которых большинство определить невозможно, исключаются. Таким образом, в основной выборке остаются только записи, для которых минимум два из трёх аннотаторов выбрали один класс.

### 2.4. Подготовка аудиоданных

Текстовые сообщения HateXplain планируется преобразовать в аудиофайлы с помощью TTS.

Для каждого сообщения будет сформирована пара:

```text
audio_file.wav → class
```

Например:

```text
hatexplain_000001.wav → normal
hatexplain_000002.wav → offensive
hatexplain_000003.wav → hatespeech
```

Полученный набор будет использоваться для отдельного обучения и тестирования модели.

## 3. Датасет Toxic Russian Comments

### 3.1. Общая характеристика

Toxic Russian Comments — русскоязычный набор комментариев пользователей социальной сети OK.ru, предназначенный для автоматического определения токсичного содержания.

Датасет содержит 248 290 комментариев.

В отличие от HateXplain, разметка Toxic Russian Comments является мультилейбл-разметкой: один комментарий может одновременно иметь несколько признаков токсичности.

Основные категории:

- `NORMAL` — нейтральный комментарий;
- `INSULT` — оскорбление;
- `THREAT` — угроза;
- `OBSCENITY` — описание или угроза сексуального насилия.

Также встречаются комбинации нескольких токсичных меток.

### 3.2. Распределение данных

Основная статистика датасета:

| Класс / комбинация | Количество | Доля |
|---|---:|---:|
| `NORMAL` | 203 685 | 82,04% |
| `INSULT` | 28 567 | 11,51% |
| `INSULT + THREAT` | 6 317 | 2,54% |
| `THREAT` | 5 460 | 2,20% |
| `OBSCENITY` | 2 245 | 0,90% |
| `INSULT + OBSCENITY` | 1 766 | 0,71% |
| `INSULT + OBSCENITY + THREAT` | 176 | 0,07% |
| `OBSCENITY + THREAT` | 74 | 0,03% |
| **Всего** | **248 290** | **100%** |

Для этого датасета характерен сильный дисбаланс: более 80% комментариев относятся к категории `NORMAL`.

Поэтому при обучении модели необходимо учитывать дисбаланс классов, особенно при оценке редких типов токсичности.

### 3.3. Качество разметки

В доступном описании Toxic Russian Comments не указаны количество аннотаторов и показатели межэкспертного согласия. Поэтому количественно оценить согласованность исходной разметки невозможно.

При использовании датасета это необходимо учитывать как одно из его ограничений. Исходные метки будут сохранены без изменений, а преобразование в общую схему классов будет выполняться отдельно.

### 3.4. Подготовка аудиоданных

Каждый комментарий планируется преобразовать в отдельный аудиофайл.

Например:

```text
toxic_ru_000001.wav → NORMAL
toxic_ru_000002.wav → INSULT
toxic_ru_000003.wav → INSULT + THREAT
```

Исходные мультилейбл-метки необходимо сохранить, чтобы при необходимости исследовать как факт токсичности, так и конкретные типы токсичного содержания.

## 4. Приведение двух датасетов к общей задаче

Главная сложность объединения HateXplain и Toxic Russian Comments заключается в различии их разметки.

HateXplain использует три взаимоисключающих класса:

- `normal`;
- `offensive`;
- `hatespeech`.

Toxic Russian Comments использует четыре основных типа:

- `NORMAL`;
- `INSULT`;
- `THREAT`;
- `OBSCENITY`;

причём одновременно может присутствовать несколько меток.

Поэтому перед объединением необходимо определить общую схему классов.

Для первоначального эксперимента можно привести оба датасета к трём укрупнённым категориям:

| Общий класс | HateXplain | Toxic Russian Comments |
|---|---|---|
| `normal` | `normal` | `NORMAL` |
| `offensive` | `offensive` | `INSULT` |
| `toxic` | `hatespeech` | `THREAT`, `OBSCENITY` и их комбинации |

Данное соответствие является рабочим укрупнением классов для эксперимента. Исходные категории двух датасетов семантически не полностью совпадают, поэтому оригинальные метки сохраняются отдельно.

При таком преобразовании часть исходной информации Toxic Russian Comments теряется. Поэтому исходные метки рекомендуется сохранить в отдельном поле даже после формирования общей категории.

Например:

```text
audio_file: toxic_ru_000123.wav
source: Toxic Russian Comments
original_labels: [INSULT, THREAT]
common_label: toxic
language: ru
```

А для HateXplain:

```text
audio_file: hatexplain_000123.wav
source: HateXplain
original_label: hatespeech
common_label: toxic
language: en
```

## 5. Формирование голосового датасета

Для обоих источников используется одинаковая общая схема:

```text
Исходный текстовый датасет
          ↓
Очистка и нормализация текста
          ↓
Проверка исходной разметки
          ↓
Приведение меток к общей схеме
          ↓
Train / Validation / Test
          ↓
TTS отдельно для каждой выборки
          ↓
Аудиофайлы + метаданные
```

## 6. План экспериментов

### Эксперимент 1. Обучение на HateXplain

На первом этапе модель обучается только на аудиоданных, полученных из HateXplain.

После обучения проводится проверка на тестовой части этого же датасета.

Цель эксперимента — определить, насколько хорошо модель способна распознавать классы на данных одного источника и одного языка.


---

### Эксперимент 2. Обучение на Toxic Russian Comments

На втором этапе модель обучается только на русскоязычных аудиоданных, полученных из Toxic Russian Comments.

После обучения проводится проверка на тестовой части этого же датасета.

Цель — определить качество распознавания токсичного содержания на русском языке и оценить влияние особенностей русскоязычных данных.


---

### Эксперимент 3. Объединённый датасет

На третьем этапе аудиоданные двух датасетов объединяются.

Объединённая выборка содержит:

- русскоязычные данные;
- англоязычные данные;
- данные из разных социальных платформ;
- различные типы токсичного содержания;
- разные исходные схемы разметки.

После приведения классов к единой схеме модель обучается на объединённом наборе.

После обучения модель проверяется на отложенной тестовой выборке.

---

## 7. Сравнение результатов

Для каждого эксперимента планируется использовать одинаковые метрики, чтобы результаты можно было сопоставить:

- Accuracy;
- Precision;
- Recall;
- F1-score;
- Macro F1;
- матрицу ошибок (Confusion Matrix).

Особое внимание следует уделить **Macro F1**, поскольку эта метрика позволяет учитывать качество распознавания отдельных классов и не позволяет большому количеству нейтральных сообщений полностью скрыть низкое качество на редких классах.

Для Toxic Russian Comments также желательно отдельно оценивать качество распознавания редких категорий.

---

## 8. Дополнительная проверка обобщающей способности

Для третьего эксперимента целесообразно выполнить не только проверку на общей тестовой выборке, но и отдельную проверку по каждому источнику.

Это позволит определить, как модель, обученная на объединённых данных, работает отдельно на англоязычных и русскоязычных примерах.

Также можно проверить модель на тестовой выборке, состоящей из данных, которые не использовались при обучении ни в одном из вариантов.

## 9. Важные ограничения эксперимента

### 9.1. Разные языки

HateXplain содержит английские тексты, а Toxic Russian Comments — русские.

Поэтому различия в качестве модели могут быть связаны не только с токсичностью, но и с особенностями языка.

### 9.2. Разные источники данных

Датасеты сформированы из разных социальных платформ и имеют различную природу сообщений.

Это также может влиять на результаты классификации.

### 9.3. Разные схемы разметки

HateXplain использует три класса, а Toxic Russian Comments — мультилейбл-разметку по типам токсичности.

Поэтому перед объединением необходимо формально определить правила преобразования исходных меток.

### 9.4. Синтетическая речь

Оба набора изначально являются текстовыми.

Аудиоданные будут созданы с помощью TTS, поэтому они не являются реальными голосовыми сообщениями пользователей.

При использовании одного и того же голоса TTS для большого количества примеров существует риск того, что модель будет запоминать особенности конкретного синтезированного голоса вместо признаков токсичного содержания.

Поэтому желательно использовать несколько голосов, различные скорости и параметры синтеза речи.

### 9.5. Дисбаланс Toxic Russian Comments

В Toxic Russian Comments категория `NORMAL` значительно превосходит остальные категории.

При объединении датасетов этот дисбаланс необходимо контролировать, иначе модель может отдавать предпочтение нейтральному классу.

---

## 10. Итог

Использование двух датасетов позволяет провести исследование в несколько этапов.

Сначала модель будет обучена и проверена отдельно на **HateXplain**, затем отдельно на **Toxic Russian Comments**. После этого данные будут приведены к общей схеме классов и объединены для обучения единой модели.

Такой подход позволяет сравнить результаты трёх вариантов:

1. модель, обученная только на HateXplain;
2. модель, обученная только на Toxic Russian Comments;
3. модель, обученная на объединённых данных.

Особенно важной частью эксперимента является последующая проверка объединённой модели отдельно на англоязычных и русскоязычных тестовых данных. Это позволит исследовать, насколько модель способна переносить признаки токсичного содержания между разными языками и источниками данных.

Таким образом, проект позволяет не только построить модель классификации токсичного голосового контента, но и исследовать влияние объёма, языка, источника и структуры разметки обучающих данных на качество работы нейронной сети.
